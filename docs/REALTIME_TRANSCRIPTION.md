# 실시간 마이크 전사 — 개발 미리보기

실시간 기능은 `codex/realtime-transcription` 개발 브랜치에 구현되어 있습니다. 배포된 `1.0.20`에는 아직 포함되지 않습니다. 기존 `4.0.20`을 `1.0.20`으로 재정의한 작업은 기능 변경과 분리했습니다.

## 사용 흐름

1. 설정의 **Live microphone transcription (preview)**에서 기능을 켭니다. 기존 OpenAI 키를 사용하며, 기본 상태는 꺼짐입니다.
2. 명령 팔레트에서 **Start live microphone transcription**을 실행합니다. 마이크 준비와 서버 설정 승인이 모두 끝난 뒤 녹음을 시작합니다.
3. 오른쪽 **Live transcription** 패널에서 자막과 녹음 상태를 확인합니다. 다른 노트를 편집해도 커서와 실행 취소 기록에 자막 변경이 섞이지 않습니다.
4. **Stop and save**를 누르면 마지막 음성 프레임을 전달하고 최종 자막을 기다립니다. 10초 안에 결과를 모두 받지 못하면 미완료로 표시합니다.
5. **Open meeting note**에서 실시간 원문과 녹음 링크를 확인합니다. **Transcribe speakers (Deepgram)**을 실행하면 저장된 녹음을 Deepgram에 보내고 화자 구분 결과를 별도 항목으로 추가합니다. 실시간 원문은 남겨 둡니다.

Deepgram 자동 처리는 기본적으로 꺼져 있습니다. 설정에서 켠 경우 정상 종료 후 실행하며, API 사용료가 별도로 발생합니다. 녹음 복구 자체는 업로드하지 않습니다. 회의 중 바꾼 언어·시간 설정은 다음 녹음에 적용됩니다.

## 저장과 복구

녹음별 폴더는 `Recordings/SpeechNote/<세션 ID>/`입니다.

| 파일 | 내용 |
| --- | --- |
| `session.json` | 녹음 식별자, 시작 시각, 노트 경로 |
| `audio-000000.part` 등 | 순서대로 저장한 녹음 조각 |
| `state-0.json`, `state-1.json` | 번갈아 기록하는 전사 상태 사본 |
| `recording.webm` | 종료 또는 복구 시 합친 녹음 |
| `transcript.md` | 실시간 원문과 화자 구분 결과 |

녹음기는 약 5초마다 전달되는 조각을 바로 저장합니다. 종료 시 파일을 합치는 작업이 실패해도 조각은 삭제하지 않습니다. **Retry saving**은 메모리에 남은 저장 실패 조각도 다시 기록합니다. 앱을 다시 실행한 뒤에는 **Recover saved live recording** 명령으로 디스크에 남은 조각을 합칠 수 있습니다.

저장이나 복구 중 회의 노트를 작성하지 못한 경우에도 **Retry saving**을 다시 사용할 수 있습니다. 녹음 파일이 만들어졌더라도 노트와 전사 상태를 모두 저장할 때까지 완료로 표시하지 않습니다. 이때의 재시도는 외부 전사를 실행하지 않습니다.

앱이 갑자기 종료되면 아직 녹음기나 저장 대기열에 있던 음성은 빠질 수 있습니다. 손실이 항상 5초 이내라고 보장하지 않습니다. 중간 조각이 누락된 경우에는 이어 붙여 완성된 녹음으로 표시하지 않습니다. 보관된 조각은 자동 삭제하지 않으며, 개별 조각이 각각 재생 가능한 파일이라는 의미도 아닙니다.

저장 위치는 Obsidian 보관함 내부입니다. 해당 폴더를 동기화하는 설정이라면 녹음과 전사문도 동기화 대상이 될 수 있습니다. 세션 파일에는 API 키를 저장하지 않습니다.

## 미리보기 범위

- 데스크톱 마이크 입력, WebM/Opus 로컬 녹음, 24 kHz PCM 실시간 전사를 지원합니다.
- 녹음 시간은 기본 45분, 최대 55분입니다. 자동 세션 연장은 포함하지 않습니다.
- 연결이 끊기거나 전송이 밀리면 실시간 전사를 중단하고 로컬 녹음을 계속합니다. 자동 재연결이나 음성 재전송은 하지 않습니다. 화면과 저장 상태에 미완료를 표시합니다.
- 무음 제거는 적용하지 않습니다. OpenAI 입력은 15초 단위로 커밋하며, 결과는 입력 순서에 맞춰 조립합니다.
- 녹음 복구·사후 처리의 현재 크기 제한은 64 MB입니다. 저장 대기 중인 조각이 8 MB를 넘으면 녹음을 멈추고 저장 확인을 요청합니다.
- 녹음 시간 제한은 기존 파일 전사 예산 설정과 별개입니다. 표시되는 시간 제한을 금액 한도로 해석하지 않습니다.
- 플러그인을 끄면 추가 전송과 사후 처리 시작을 중단합니다. 이미 전송된 요청은 서버에서 처리될 수 있습니다.
- Deepgram 화자 정보가 없거나 부분 결과이면 완료된 화자 구분으로 표시하지 않습니다.

## 검증 범위

자동 테스트에서는 저장 실패 후 복구, 손상된 상태 파일, 중복 종료, 인증 중 취소, 서버 설정 승인 대기, 자막 완료 순서, 마지막 음성 프레임, 전송 지연, 미완료 처리, 원문·사용자 메모 보존, 복구 시 업로드 방지, Deepgram 재시도 취소를 확인합니다.

실제 Obsidian의 마이크 권한, Electron의 WebM 녹음, 실제 OpenAI 계정의 모델 접근 및 세션 이벤트, Deepgram의 한국어 화자 구분, 긴 회의에서의 지연·음질은 실제 환경 확인이 남아 있습니다. 이 확인 전에는 새 기능을 정식 릴리즈로 배포하지 않습니다.

API 구성은 [OpenAI 실시간 전사 공식 문서](https://developers.openai.com/api/docs/guides/realtime-transcription)를 기준으로 작성했습니다. 팀원 문서 원본과 검토·진행 기록은 Git에서 제외한 `docs/reviews/`에 보관합니다.

사후 화자 구분 요청은 `model=nova-3`를 명시합니다. 기존 파일 전사의 호환성 변환과 분리했으며, 한국어 지원은 [Deepgram의 공식 Nova-3 변경 기록](https://developers.deepgram.com/changelog/2025/11/4)에서 확인했습니다.
